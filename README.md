# Task-1-Post-Launch-Health-Incident-Command

## Task
Task 1 — Post-Launch Health, Incident Command & Sprint Planning

## Objective
Establish post-launch truth across funnel, revenue, retention and quality, rank the biggest problems using evidence, and create a Phase-3 analytics backlog tied to decisions.

## Dataset
`Task1_Post_Launch_Health.csv`

## Main Metrics
- Visitors
- Signups
- Application Starts
- Document Upload Success
- Submissions
- Revenue
- 7-Day Retention
- Quality Defects
- Support Tickets
- API Failures

## Method
1. Load and validate the dataset.
2. Check duplicates and data quality.
3. Calculate funnel conversion metrics.
4. Analyze revenue and retention.
5. Measure quality and reliability indicators.
6. Rank the biggest problems using evidence.
7. Connect each problem to a decision.
8. Create a Phase-3 analytics backlog.

## Key Findings
- 43,516 visitors
- 8,992 signups
- 5,938 application starts
- 4,338 successful document uploads
- 2,262 submissions
- $103,735.72 revenue
- 52.02% 7-day retention
- 203 quality defects
- 527 support tickets
- 1,099 API failures

## Priority Areas
### P0
- Investigate funnel leakage.
- Correlate API failures with funnel impact.
- Identify high-impact reliability problems.

### P1
- Analyze retention cohorts.
- Classify recurring quality defects.
- Add freshness and sanity monitoring.

## Conclusion
The project converts post-launch data into evidence-backed decisions. Every important metric is connected to a source, calculation, validation check, and action.
